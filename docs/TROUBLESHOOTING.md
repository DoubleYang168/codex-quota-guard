# 常见问题

## 工具或原生按钮没有出现

确认 Node 可从 PATH 访问、插件安装成功且连接已启用。重新加载插件，使用新聊天，必要时重启桌面端。原生 MCP Apps 面板可发现不代表所有宿主都能显示；可直接用插件打开浏览器管理页。

CLI 安装命令在不同版本可能变化。先按 [兼容性](COMPATIBILITY.md) 核对，再参考 [INSTALL.md](../INSTALL.md)；不要手改兼容版本绕过检查。

## 点击立即检查，聊天没有停止

依次核对：

1. 会话已加入监控，而非仅出现在列表。
2. 启用监控和自动控制已点击“保存设置”；阈值已点击“保存规则”。
3. 剩余额度不高于暂停阈值，并且目标当前确实运行中。
4. 会话下方是否显示桌面未加载、身份变化、排队输入、不兼容或结果不明的原因。
5. 在原桌面打开目标会话，确认当前轮次状态，检查运行记录。

观察模式只记录拟停止。背景定时检查对同周期新工作有保护；显式立即检查会重新判断，但仍保留身份等检查。不要用反复点击替代排查。

## 达到恢复阈值仍未继续

只有插件因额度暂停的记录会自动恢复，手动停止不在此列。检查周额度、账户是否变化、原 Goal／任务是否被替换、是否已有新轮次或排队消息，以及桌面是否加载目标会话。

严格 100% 时，一个会话恢复后的消耗可能让其他会话继续等待。完整 Goal 自动恢复仍是待验收能力。

## 结果不明、needs_attention

检查原聊天里是否已经停止或发出了续跑，不要反复提交。确认后可取消旧恢复或按页面说明解除阻止，再决定是否手动继续。解除阻止不证明前次操作成功，不重发指令。

## 管理页离线或旧链接失效

退出后台再启动后端口／页面凭证可能变化。用插件或 `ui` 获取新链接；旧页面自身不能重新拉起后台。不要公开带 `#` 凭证的链接。

## 两个入口显示不同名单／配置

核对数据目录。源码 CLI 默认 `.runtime`，源码安装脚本默认固定为 `.runtime/user`；环境变量和安装指针还可能覆盖默认值。不同目录会启动不同后台。先停止错误实例，再使用原目录，不要让两个实例管理同一聊天。

## 想停插件，却只关了网页

关闭浏览器不会停止后台；停用监控也不退出后台。使用原生面板“退出后台”或在同一数据目录执行 `node bin/quota-guard.mjs stop`，再用 `service-status` 确认离线，最后禁用／卸载宿主插件。

## 状态或令牌损坏

停止后台后核对路径、权限与备份。程序不会自动覆盖损坏的状态或令牌。不要为了消除报错直接修改状态 schema 或删掉尚需恢复的记录。

## 提交问题时提供什么

提供插件、Node、CLI、桌面版本；可复现步骤；预期／实际结果；已脱敏的错误码。删除用户名、工作目录、会话 UUID、聊天正文、账户数据、控制令牌和页面凭证。截图使用模拟数据；敏感漏洞按 [SECURITY.md](../SECURITY.md) 私下报告。
